# EPIC-08. Private Registry and Governance

**Status:** Proposed
**Milestone:** M4
**Owner:** TBD
**Last updated:** 2026-03-28

## Objective

Make Guild realistic for team pilots by supporting private distribution, provenance, and audit-friendly operation.

## Why now

Once Guild has useful, trusted first-party playbooks, the next barrier is team adoption and governance.

## In scope

- private pack sources
- bundle signing and signature verification
- run history export
- governance docs and pilot checklist

## Out of scope

- public marketplace work
- broad sales / admin portal ambitions
- full enterprise policy engine

## Deliverables

- private pack source configuration
- signature verification
- audit export
- governance guide
- pilot onboarding docs

## Dependencies

- EPIC-06 and EPIC-07

## Risks

- provenance bolted on too late
- governance written after technical decisions harden
- private distribution that does not match verification semantics

## Exit criteria

- one team can run a private pilot with signed packs
- audit export is legible to non-authors
- governance docs explain retention, approvals, and trust labels clearly
